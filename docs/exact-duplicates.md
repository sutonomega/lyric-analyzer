# 完全一致曲の再追加防止と既存整理

Issue #14の利用者要望に対応。既存データの整理は明示操作だけで行い、起動時には自動削除しない。

## 再追加の防止

Title・Styles・最新Lyricsの文字列がすべて一致する場合、手動保存は既存曲の編集を案内して中止する。曲名の保存時の前後空白除去を除き、大小文字・全半角・改行・歌詞の空白を勝手に統一して一致としない。同じタイトルでも本文やStylesが違う場合は別曲を保持する。

フォルダーは従来の完全一致スキップを維持。JSONはIDが違っていても完全一致を検出し、テーマ・制作日・タグ・全改訂本文も一致すればスキップする。同じ最新内容に異なるメタデータや改訂がある場合は、既存曲の確認を案内して取り込み全体を取り消す。ID衝突時のcopy指定でも完全一致の追加は行わない。各操作はBEGIN IMMEDIATE内で既存内容を再確認し、同時登録でのすり抜けを防ぐ。

## 既存の整理

`duplicates.consolidate(library)` は、Title・Styles・テーマ・制作日・タグ・全改訂本文・曲単位の除外条件を比較する。日時・内部IDの差だけで別内容としない。分析対象として使われている登録を優先して残し、その後は作成日とIDの順で決める。

最初の変更前に全データJSONを作成・検証し、backupsへ書き込んで同期する。失敗時は曲を変更しない。履歴や除外から参照されていない重複は削除し、参照されるものはDB移行8のsongs.duplicate_archived=1で履歴用に保持する。通常一覧・新規比較・語句集計・制作日編集・楽曲JSONは有効曲だけを使う。過去の分析payload・根拠・評価・AI候補は書き換えない。バックアップ形式1はDB版5〜8に対応し、旧版は新項目0で移行する。全データバックアップには履歴用原本も含め、復元画面で通常曲と参照用曲の件数を区別する。

整理前のバックアップを復元すれば重複も当時の状態に戻る。通常の追加操作での防止と、明示的な全データ復元は別の操作である。過去の分析結果は当時の比較母数を保持するので、現在の曲数による結果が必要なら総合分析し直す。

## 検証（2026-11-18）

全435テストと型チェック成功。完全一致の手動保存・編集の拒否、同名別内容の保持、JSONの別IDとcopy指定のスキップ、追加情報の衝突時の中止、再実行、旧版バックアップ移行、整理前後の復元、バックアップ失敗時と整理途中の失敗時の取り消し、同時登録、整理前から開いていた画面の比較対象選択の更新を確認した。

専用の実Streamlitで、自作データの整理後に曲が1件だけ表示されること、完全一致の保存が案内付きで拒否されること、元の分析履歴が変わらず表示できることを確認した。新しい警告・例外はなかった。

利用者データはコピーで事前に試行し、原本のバックアップを残して整理した。有効曲のTitle・Styles・テーマ・制作日・本文・タグ、および全分析履歴・参照リンク・候補・評価・辞書・除外の一致を確認。参照整合性と整理後のバックアップ検証も成功。実データ・曲名一覧・バックアップは公開リポジトリに含めず、AIも呼び出していない。
