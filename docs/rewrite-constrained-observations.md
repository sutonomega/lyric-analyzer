# 原文を固定する方式の検証と採用判断

対応Issue：#11。検証日は2026-11-16、結果の整理・採用判断は2026-11-18。Issue #9は利用者確認により完了済みとし、今回の検証とは区別する。

## 比較した内容

既存の試用local-rewrite-2と、検証専用のlocal-rewrite-3を同じ自作8例で各1回比較した。モデルはqwen2.5:3b。指示本文は同じで、3だけがJSON Schemaでline_idとoriginalの許容値を入力値1つに制限する。温度0.4、生成上限1,200トークン、応答待ち45秒は従来どおり。失敗の自動再試行は行っていない。

Ollamaへの`format`によるJSON Schema指定は[公式の構造化出力仕様](https://docs.ollama.com/capabilities/structured-outputs)を参照。返答後もアプリと同じ原文照合・候補形式の検証を行う。制約を付けたことを理由に検証を省略しない。

|方式|試行|生成・検証成功|失敗|
|---|---:|---:|---:|
|従来の試用 local-rewrite-2|8|7|1|
|原文固定の検証専用 local-rewrite-3|8|5|3|

従来方式の失敗1件は原文または対象行IDの不一致。検証専用方式ではこの不一致は発生しなかったが、候補の方向・本文の形式不一致2件、説明の形式不一致1件が残った。全体の生成成功が改善したとは言えない。各1回の確率的な生成であり、一般的な成功率や方式の優劣を推定しない。

## 意味の問題は残る

原文「昨日、妹が鍵を返した」に対する検証専用方式の意味保持案は「昨日、妹に鍵を返した」。返す側と受け取る側が変わっている。

原文「私は切符を二枚買った」に対しては「私は切符を一枚だけ買いました。」となり、数量と語調が変わった。原文を返す欄の正しさと、候補が意味を保つことは別である。

## 採用判断

画面の「候補の作り方」には追加しない。標準・既存試用の指示、生成パラメーター、保存データ、バックアップ形式は変更しない。検証専用方式の結果を通常の候補履歴へ取り込むことにも対応しない。

検証コマンドだけで比較方式を指定できるようにし、データ・モデル・指示に加えて、各要求の応答スキーマのハッシュを記録する。指示本文が同一でも、応答制約が異なることを区別できる。全生成結果と失敗は[比較記録](rewrite-constrained-evaluation.md)に掲載する。利用者の歌詞・DBは使用していない。

今回の結果は構造上の実験に限る。Issue #11の自然さ・具体性・意味保持についての利用者確認は残す。
