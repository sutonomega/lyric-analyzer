# 直接生成と原文固定を組み合わせた試用方式

対応Issue：#11。検証日：2026-11-18。Ollama 0.31.1、gemma4:12b、同梱の自作8例を使用。Issue #9は完了済みのまま。

## 変更した範囲

既存の直接生成local-rewrite-4と、新しいlocal-rewrite-5を各例1回比較した。両方式の指示本文、think:false、温度0.4、出力上限1,200トークン、待ち時間45秒は同じ。5だけが応答Schemaのline_idとoriginalの許容値を入力値1つに限定する。各例の入力・生成条件・指示ハッシュが一致し、応答Schemaのハッシュだけが異なることを照合した。

これは返答の引用元の取り違えを抑える制約であり、候補本文が意味を保つことの判定ではない。応答後の原文・形式・生成完了の照合も引き続き行う。制約を付けても、不正な応答を無条件に信用しない。

## 自作8例の結果

|方式|試行|生成・検証成功|失敗|
|---|---:|---:|---:|
|local-rewrite-4|8|8|0|
|local-rewrite-5|8|8|0|

今回の比較では旧・新とも8/8件が成功した。以前の別の試行で旧方式に原文不一致があったが、今回の結果から一般的な再発率や成功率の改善は断定しない。再試行や失敗例の取り直しはしていない。

## 候補本文に残る確認

- 新方式の可能性の例は「明日は君と会えることだろう」。原文「会えるかもしれない」より確信が強くなる可能性があり、語調と意味の確認が必要。
- 数量の例では新旧とも「私は切符を二枚手に入れた」。枚数を維持しても、購入したことが明示されていない。
本文の有用性、自然さ、意味保持を自動で評価してはいない。すべて未評価のまま記録し、人の確認を残す。[全16回の本文と補助確認](rewrite-bound-direct-evaluation.md)を参照。

## 画面と既存データ

画面の「候補を直接生成（試用）」は5を使用し、選択肢は標準・意味保持の試用・直接生成の3つを維持する。既定は従来の標準のまま。旧4の選択状態が残っていた場合は新5へ切り替えるが、以前の送信確認を引き継がず、生成前に再確認を求める。旧4の候補履歴・読み・人の評価は書き換えない。

旧4は履歴とバックアップ、検証コマンドで引き続き扱える。評価集計は4と5を別条件として数える。検証専用3は画面に追加しない。DB版7とバックアップ形式は維持する。

旧・新の混在バックアップ、設定と応答Schemaの分離、引用符や全角文字の原文、別要求への影響、制約に反する応答の拒否、旧選択の更新と再確認、履歴の不変、評価集計の分離を検証。自作歌詞の実画面で新5の生成・保存・バックアップ検証・確認解除・集計を確認した。全394テストと型チェックが成功。

利用者の歌詞・DBは使用せず、確認後はモデルを解放し検証用の画面とOllamaを停止した。Issue11は着手時と公開前に再照合し、候補本文の意味・自然さ・具体性の利用者確認を残す。
