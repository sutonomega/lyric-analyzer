# 検索専用モデルによるHTTP 400の修正

2026-11-18、利用者から候補保存時のHTTP 400を報告された。利用者が選択した組み合わせは `embeddinggemma:300m` と「標準」。自作の確認文で同じモデルにチャット要求を送り、HTTP 400と `does not support chat` を再現した。Ollama自体には接続できており、停止・再起動が必要な障害ではなかった。

従来はインストール済みローカルモデルを用途に関係なく候補生成の一覧に表示していた。今回、モデル情報の `capabilities` に `completion` があるローカルモデルだけを表示するよう修正。検索専用・機能不明・外部モデルを除外する。旧一覧のキャッシュは使用せず、再確認を促す。モデルの自動取得や推奨順位の追加はしない。

生成直前にも対応を確認し、非対応モデルには歌詞を渡す前に説明して中止する。モデル情報の取得ではモデル名だけを送り、歌詞は送らない。機能情報を返さない旧サーバーも、文章生成できると推定して送信しない。保存済み履歴や意味検索用のEmbeddingGemmaの選択には変更を加えない。

全422テスト、型チェック、差分チェックが成功。機能情報の不正・欠落、外部モデル、検索専用モデルの除外、生成直前の拒否、古い一覧と検索モデルの選択状態からの更新、確認前には生成しないことを検証した。

専用データ保存先・8765ポートのStreamlitでagent APIを使い、実接続のモデル一覧にEmbeddingGemmaが表示されないこと、gemma4:12bの直接生成方式で自作短文から3候補を生成して保存できることを確認した。バックアップ検証・生成条件変更時の確認解除・候補集計も成功。コンソールに追加の警告や例外はなかった。検証画面のみ終了し、既存Ollamaは停止していない。利用者の歌詞・DBは使用しない。

着手時・公開前にIssue #11と照合し、今回の範囲を非対応モデルの誤選択対策に限定。候補本文の自然さ・意味保持の利用者評価は引き続き未完了とする。

モデル機能情報の仕様：[Ollama公式API仕様](https://github.com/ollama/ollama/blob/main/docs/openapi.yaml) の `/api/show`。
