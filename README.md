# Lyric Analyzer

Suno向け歌詞制作を支援する、Windows用ローカルWebアプリの開発プロジェクトです。

過去曲で繰り返し使う語句と、辞書に登録した定型表現を組み合わせて分析します。指摘の根拠を確認し、修正するかを利用者が判断できます。

## 現在の状態

歌詞の保存・検索・編集・削除、タグ、改訂履歴、JSON入出力、単語・フレーズ集計、過去曲比較、登録辞書と文型による定型表現の確認を利用できます。外部AIは使用しません。

- 想定構成：Python / Streamlit / SQLite / SudachiPy
- MVP：歌詞管理、語彙・フレーズ集計、過去曲比較、定型表現辞書、除外設定、分析履歴
- 外部AIによる文脈評価と言い換えは次段階

仕様・データ設計・受入条件・開発計画は [仕様書](docs/specification.md) を参照してください。

歌詞、データベース、APIキーはGit管理に含めません。

## フォルダーから一括取り込み

「フォルダーから歌詞を一括取り込み」を開き、フォルダーパスを入力するか「フォルダーを選択」を使います。見出し付きの `.txt` / `.md` / `.markdown` が対象です。1ファイル1曲として、次の形式で用意してください。

```text
Title: 夜の改札
Styles: mellow pop, piano, female vocal
Lyrics:
[Verse]
改札の端で切符を折った
[Chorus]
最終電車の窓を見送る
```

Markdown見出しの `# Title` / `# Styles` / `# Lyrics` の次の行に内容を書く形式や、`**Title:**`、`[Title]` なども読み取れます。見出しは大文字・小文字を区別しません。Titleは空でない1行、Stylesは複数行または空、Lyricsは空でない本文とし、Lyricsの見出しを最後に置きます。Lyrics以降はファイル末尾までを歌詞として保持し、Sunoの `[Verse]` や `[Chorus]`、改行も残します。Stylesはテーマとは別の項目で保存・検索・編集でき、歌詞の単語集計には含めません。

1. フォルダーと文字コードを指定して「確認」を押します。自動判別はBOM付きUTF-16、UTF-8（BOM対応）、CP932に対応し、UTF-8／CP932を明示することもできます。
2. 読み取れた曲と、エラーになったファイルを確認します。Title・Styles・Lyrics全文のプレビューも表示できます。
3. 取り込む曲を選択し、重複確認と追加／スキップ予定を確認してから「確認した曲を一括登録」を押します。

既存曲は上書きしません。Title・Styles・Lyricsがすべて同じ曲は、フォルダー内の重複も再取り込みもスキップします。同名で内容が違う曲や、歌詞が同じ別タイトルは既定でスキップし、チェックを入れた場合だけ別曲として追加します。DBへの登録時にも重複を再確認します。曲を新規追加した後は、比較対象を編集中の自曲以外の全曲に戻します。

エラーがある場合は、そのファイルを除いて取り込むことを明示的に選ぶまで登録できません。登録処理で失敗した場合は今回分をまとめて取り消し、既存曲を保持します。確認後にファイルを編集した場合は再確認してください。取り込みは確認時点の内容を使用し、元ファイルは変更しません。

1回500ファイル、合計20MB、1ファイル2MB、Lyricsは20,000文字までです。パス指定では子フォルダーを含むか選択できます。ブラウザのフォルダー選択は子フォルダーも対象です。パス指定時のリンク・ジャンクションはたどりません。

## Windowsで起動

1. Python 3.12（64bit、Python Launcherを含む）をインストールします。
2. このリポジトリを取得し、`start.cmd` をダブルクリックします。
3. 初回は依存ライブラリをインストールします。表示された `http://127.0.0.1:8501` をブラウザで開きます。
4. 終了するときは起動したウィンドウで Ctrl+C を押します。

起動はローカルPCに限定します。Streamlitの利用統計送信も起動時に無効化します。歌詞を外部AIへ送る処理はありません。

保存先は `%LOCALAPPDATA%\LyricAnalyzer\library.db` です。`LYRIC_ANALYZER_DATA_DIR` 環境変数で変更できます。曲の削除は全改訂も削除するため確認が必要です。

## データの持ち出しと復元

「全曲をJSONで書き出す」で歌詞・タグ・全改訂を保存できます。取り込むファイルは10MB以内のUTF-8 JSONです。取り込み前に曲名・改訂数・既存IDとの重複数を確認し、重複曲をスキップするか、別曲として追加するか選びます。既存の歌詞は上書きしません。形式やハッシュに誤りがある場合、取り込みを中止します。

このJSONは楽曲ライブラリ用です。分析履歴・設定も含めて保存する場合は「全データのバックアップ・復元」を使います。古いDBは起動時に移行し、既存の歌詞を保持します。

編集した定型表現辞書もDBに保存します。楽曲JSONには含みませんが、全データのバックアップには含みます。

「行・セクションを確認」では未保存の歌詞も確認できます。単独行のブラケットタグを本文から分け、改行・句点・感嘆符・疑問符を解析区間の境界にします。内部ではNFKC正規化と原文位置の対応を保持します。

## 単語・フレーズを分析

歌詞を入力し「単語・フレーズを分析」を押すと、保存せずに集計できます。集計種類を切り替え、上位50件の回数・表記別内訳・出現行と、選択した語句の原文を確認できます。

- 単語：名詞・動詞・形容詞を原形別に集計。「消える」「消えた」の「消え」は「消える」にまとまります。英数字は翻訳・語形統一せず、英字の大文字・小文字も区別します。
- フレーズ：助詞・助動詞を保持した連続2〜5形態素。内容語を含むものだけを抽出し、改行・句読点・記号・空白をまたぎません。「ほどけた」と「ほどけていく」は別の表現として残ります。
- 原文一致／全角・半角を統一：後者はUnicode NFKCで統合します。活用形や同義語の統合は行いません。NFKCには半角濁点の合成や互換文字の展開も含まれます。
- 回数は繰り返されたサビも含む生の出現数です。「異なる本文行数」は、完全に同じ本文の行をまとめて数えます。過去曲の使用曲数ではありません。

既知のセクションタグは集計から除外します。未知タグはチェックで集計に含められます。結果は最後に分析した入力のものなので、編集後は再分析してください。個別分析の結果はアプリ実行中のみ保持します。履歴に残す場合は総合分析を使ってください。1回の分析は20,000文字までです。

SudachiPy 0.7.0、core辞書20261015、分割モードAを固定しています。初回セットアップでは辞書もダウンロードしますが、分析時はネット接続不要です。辞書の分割・品詞判定によって、人が考える語句と区切りが異なる場合があります。[SudachiPy公式資料](https://github.com/WorksApplications/sudachi.rs/tree/develop/python)を参照してください。

## 過去曲との重複を比較

歌詞エディターの「比較対象の曲」で過去曲を選び、「過去曲と比較」を押します。初期値は編集中の曲を除く全曲です。各曲の最新版だけを比較し、同じ曲の旧改訂は数えません。未保存の入力も比較できます。任意で楽曲登録日の開始・終了を指定できます（日付は日本時間、両端を含む）。

- 使用曲数、比較曲数、過去曲の出現回数、入力中の出現回数を別々に表示します。
- 単語原形、フレーズ原文一致、全角・半角を揃えたフレーズ一致を切り替えられます。
- フレーズは2〜5形態素に加え、句読点・空白で区切った本文同士の共通部分から6文字以上の原文一致を補助的に抽出します。補助抽出は意味類似の判定ではなく、すべての部分文字列を列挙する方式でもありません。
- 短い一致が入力側・過去曲側ともに長い一致の同じ出現箇所に収まる場合はまとめます。別の出現箇所がある短い一致は残します。チェックを入れるとまとめる前の一覧も確認できます。
- 10曲以上の比較では、3曲以上かつ20%以上で使用されたフレーズを「頻出」と表示します。10曲未満では2曲以上の一致を参考表示し、単語は常に参考情報です。
- 「重複箇所を確認」で入力中と過去曲の引用行を確認し、「引用元の歌詞を開く」で選んだ曲の全文を展開できます。該当行には印が付きます。

歌詞全文が同じ別曲は注意表示しますが、曲IDが異なるため曲数には含みます。自動統合はしません。比較結果には実行時点の曲名・改訂・歌詞・ハッシュを保持するため、その後の編集で引用が変わることはありません。最新の変更や比較条件を反映するには再比較してください。個別比較を終了後も履歴に残す場合は総合分析を使ってください。20,000文字を超える曲が対象にある場合、無断で除外せずエラーを表示します。

## 定型表現と文型を確認

入力した歌詞で「定型表現を確認」を押すと、登録ルールへの一致を理由・見直しの観点・原文の行とともに表示します。歌詞を保存したり自動修正したりはしません。AI生成の確率や独自性の採点でもありません。

初期辞書は手作業で作成した5ルールです。「ほどけていく」「消えない想い」「心の奥で」「光を探して」の4表現と、「登録した抽象名詞＋が／は＋登録した消失動詞」の文型を含みます。一般的なAI歌詞の統計に基づくリストではありません。

- 登録表現はNFKCで全角・半角等を揃え、単語の境界に一致する箇所を検出します。「消えない想い出」の一部分を「消えない想い」として指摘することは避けます。改行・句点等の区間境界をまたぎません。
- 文型は名詞・助詞・動詞の3語が連続する場合に限定します。語の活用は原形で照合し、直後の「ない・ぬ・ず」を除外します。文全体の意味や複雑な否定を理解する機能ではないため、結果は「文型候補」と表示します。
- 「定型表現辞書を編集」を開き、新規追加、登録条件・理由・見直しの観点の編集、有効／無効の切り替えができます。文型の名詞・動詞は解析器が返す原形をカンマ区切りで指定します。正規表現や任意コードは使いません。
- 保存内容が変わったときに版番号が上がります。初期ルールの編集・無効化は再起動しても保持します。過去に表示した指摘の理由はそのときのルール版のままです。歌詞や辞書の編集後は再確認してください。

## 総合分析・除外・履歴

「総合分析して履歴に保存」で、同じ入力・比較条件に対して過去曲比較と登録ルールの確認を一度に実行します。未保存の歌詞も分析履歴には保存するため、このボタンの操作でローカルDBに歌詞が残ります。個別の分析ボタンは従来どおり履歴を保存しません。

指摘は「過去曲頻出／参考＋登録ルール」「過去曲頻出／参考」「登録ルール」「単語参考」「閾値未満の一致」の順に並びます。包含する同一箇所の根拠を結び付け、別の箇所や単に隣り合う表現は統合しません。原文行・過去曲の引用・ルール版と理由を確認できます。小規模ライブラリの参考判定は頻出の断定とは区別します。

- 「この表現を除外」には理由の入力が必要です。「今回の分析だけ」「この曲で許容」「全体で除外」を選べます。未保存の入力は曲単位で除外できません。
- 除外は同じ種類（単語／フレーズ）と除外キーの全出現に適用します。単語のキーは原形、フレーズはNFKC表記です。部分一致や、含まれる別の語句までまとめて除外する処理は行いません。
- 「除外した指摘も表示」で理由を確認できます。「除外設定を管理」から解除可能です。除外しても回数や分析根拠は変えません。
- 「分析履歴を開く」で再起動後も結果を確認できます。入力、比較元の改訂・ハッシュ・引用、辞書とルール版、分析条件・解析器版を保存し、曲や辞書を後で編集しても当時の根拠を保持します。
- 履歴は保存時の除外設定で表示します。「現在の除外設定で表示」を選ぶと、保存後の除外・解除も反映できます。除外操作は元の分析結果を書き換えません。
- 1件の分析結果をJSONで書き出せます。これは確認・保管用のスナップショットで、楽曲JSONの取り込み対象とは異なります。履歴・辞書・除外もまとめて移行する場合は全データのバックアップを使います。

曲を削除する前に、その曲が入力または比較元に含まれる分析履歴の件数を表示します。削除すると関連履歴と曲単位の除外も同時に削除します。全体の除外設定は独立した設定として残ります。

## 全データのバックアップ・復元

「全データのバックアップ・復元」を開き、「バックアップを作成」→「全データのバックアップを保存」でJSONを保存します。歌詞・全改訂・タグ・辞書と有効状態・除外・分析履歴・評価記録を含みます。作成ボタンを押した時点のデータなので、編集後は再作成してください。

復元では専用のバックアップJSON（100MB以内）を選び、作成日時と件数を確認します。チェックを入れて「確認した内容で復元」を押すと、現在の全データを置き換えます。曲を追加する楽曲JSON取り込みとは異なります。入力ファイルのSQLやテーブル定義は実行せず、アプリで定義した表だけを再構築し、検証値・形式・参照・歌詞ハッシュ・履歴の引用位置を確認してから復元します。

復元直前の全データは、DBと同じ保存先の `backups/before-restore-*.json` に自動退避します。退避に失敗した場合は復元しません。元に戻すには、その退避ファイルを同じ画面で選んで復元します。復元後は画面の選択や一時的な表示状態をリセットします。対応形式は全データ形式1・DB版5／6です。現在のDB版は6で、版5のバックアップを復元する場合はStylesを空文字で補完します。上限を超える場合はエラーを表示し、復元できないバックアップを作成しません。

## MVPの評価

履歴または総合分析の「上位指摘の有用性を評価」で、保存時の上位最大10件を「有用／意図的な表現／誤検出」に分類し、メモを保存できます。未評価は分母から除外し、評価済み件数と有用率を併記します。1件だけの100%をMVP合格とは扱いません。記録はJSONで書き出せ、全データのバックアップにも含まれます。

現在は自作30例の正解テストと、自作20曲×各2,000文字の性能計測を実施済みです。利用者の実歌詞10〜20曲と人の判断による有用性評価は未実施です。Issue #9はこの評価を含めて継続します。計測条件・数値・残る確認事項は [MVP検証記録](docs/mvp-validation.md) を参照してください。

再計測は次のコマンドで実行できます。専用の一時DBを使うため、利用者のライブラリを変更しません。結果キャッシュを使わず、比較・定型表現検出・結果統合・JSON化・SQLite履歴保存まで測ります。UI描画時間は含みません。

```powershell
.\.venv\Scripts\python.exe -m lyric_analyzer.evaluation --output userdata/evaluation/result.json --repeats 3
```
